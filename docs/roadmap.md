# 다음 구현 단계

이 문서는 확장 제안입니다. 현재 동작은 [구조 문서](architecture.md)를 기준으로 확인하세요. 아래 기능에 확정된 일정은 없습니다.

## 현재 완료 범위

Docker에서 UI와 서버를 실행하고, 샘플 또는 사용자 JSON을 원본·정제·마트로 처리합니다. 실행 기록, 데이터셋 관계와 데이터 조회 답변을 확인할 수 있습니다. 현재 작업 유형과 데이터 형식은 상품 가격 예제로 제한됩니다.

기본 예약 실행도 구현했습니다. 워크플로마다 여러 매일·요일별 스케줄을 등록하고, `Asia/Seoul` 또는 `UTC`에서 실행 시간을 정합니다. 편집·일시정지·재개·즉시 실행·삭제를 지원하며, 서버의 15초 간격 확인 루프가 실제 실행을 시작합니다. 26주 실행 캘린더는 저장된 최근 1,000개 실행과 날짜별 로그를 연결합니다.

## 기존 수집 코드 연결

목표는 사용자가 작성한 Python 크롤러를 수정 없이 연결하거나, 작은 입출력 어댑터만 추가해 실행하는 것입니다.

- 실행 파일, 입력 설정과 출력 데이터 형식을 정의합니다.
- 의존 패키지와 실행 이미지를 지정합니다.
- 종료 코드, 표준 출력, 표준 오류와 결과 파일을 수집합니다.
- 시간 제한과 취소를 포함해 서버 프로세스와 사용자 작업을 분리합니다.
- 작업에 필요한 디렉터리와 네트워크만 제공하는 실행 범위를 정합니다.

완료 기준은 예제 크롤러 하나를 등록해 원본 데이터셋을 생성하고, 실패·시간 초과를 UI에서 구분하는 것입니다. 임의 코드 실행을 추가하기 전에 실행 격리와 권한을 검증해야 합니다.

## SQL과 저장소 연결

목표는 고정된 상품 처리 로직을 사용자가 작성한 변환과 데이터 마트로 확장하는 것입니다.

- 데이터 소스와 저장 대상의 연결 규칙을 정의합니다.
- SQL 실행, 파라미터와 결과 스키마를 기록합니다.
- 데이터는 저장소에 두고 작업 사이에는 데이터셋·파티션 참조를 전달합니다.
- 부분 실패 중 결과 공개와 중복 적재 규칙을 정합니다.
- 현재 JSON 상태를 옮길 마이그레이션과 백업·복원 방법을 제공합니다.

완료 기준은 외부 저장소 한 종류에서 원천을 읽고 SQL 변환으로 마트를 만든 뒤 재실행 결과가 일관되는 것입니다.

## LangGraph와 모델 연결

목표는 현재의 데이터 조회 기능을 AI 워크플로에서 호출할 수 있는 도구로 제공하는 것입니다.

- 먼저 마트 조회 도구의 입력과 출력 형식을 고정합니다.
- LangGraph의 질문 분류, 도구 호출과 응답 단계를 연결합니다.
- 모델 제공자 설정과 비밀 정보 저장을 분리합니다.
- 조회 허용 범위, 건수와 실행 시간을 제한합니다.
- 답변에 데이터셋, 데이터 기준 시각과 조회 실행을 연결합니다.
- 정형 데이터 조회와 문서 검색은 서로 다른 도구로 다룹니다.

완료 기준은 실제 LangGraph 실행이 조회 도구를 호출하고, 도구 실패와 오래된 마트를 사용자에게 표시하는 것입니다. 모델 없이 계산한 응답과 모델이 생성한 응답을 UI에서 구분해야 합니다.

## 실행 복구와 기간 재처리

목표는 구현된 로컬 예약을 바탕으로 작업 실행과 복구를 분리하는 것입니다. 현재는 다음 실행 시각을 먼저 저장하므로 중단 시 해당 회차가 누락될 수 있고, 중지 중 지난 예약도 한 번으로 합쳐 실행합니다.

- 작업 대기열과 실행기 상태를 도입합니다.
- 동시 실행 수, 시간 제한과 자동 재시도를 정의합니다.
- 워크플로의 저장 버전과 배포 버전을 구분합니다.
- 실행기 중단과 관리 서버 재시작 후 실행 중인 작업의 상태를 복구합니다.
- 기간 재처리, 단계 재개와 전체 재실행의 규칙을 나눕니다.

기존 실행 엔진 연동과 제한된 자체 실행기 중 어느 방식이 유지관리 부담을 줄이는지 비교한 뒤 선택합니다. 완료 기준은 관리 서버와 실행기의 중단을 재현해도 실행 기록과 데이터 공개 상태가 일치하는 것입니다. 캘린더의 1,000개 기록 제한을 넘어서는 이력 보관 정책도 별도로 정해야 합니다.

## 첫 클라우드 실행 어댑터

목표는 로컬에서 검증한 작업을 사용자가 연결한 클라우드에서 실행하는 것입니다. 첫 제공자는 데이터 위치, 보유 계정과 운영 비용을 확인한 뒤 선정합니다.

- 데이터 커넥터와 실행 어댑터의 책임을 나눕니다.
- 한 제공자의 자격증명, 권한과 네트워크 연결을 검증합니다.
- 작업 제출, 실행 ID 추적, 로그 수집, 취소와 자원 정리를 지원합니다.
- 작업 결과가 위치한 데이터셋 참조를 로컬 관리 서버에 기록합니다.
- 비용은 확인된 값과 추정값을 구분해 표시합니다.

완료 기준은 실제 원격 작업 하나의 실행과 취소를 확인하고, 남은 자원 및 생성 데이터의 위치를 추적하는 것입니다. 클라우드 설정 등록만으로 완료 처리하지 않습니다.

## 협업과 공개 운영

공용 서버에서 쓰기 전에 인증, 프로젝트별 권한과 비밀 정보 관리를 추가해야 합니다. 여러 사용자가 동시에 편집할 때 변경 충돌을 다루고, 공유된 실행 기록과 데이터 조회 권한을 일치시켜야 합니다.

공개 저장소에는 호환성 정책, 데이터 마이그레이션, 확장 가이드와 비공개 보안 제보 채널을 추가합니다. 새 사용자가 문서만 보고 설치하고 자신의 수집 코드를 연결해 복구까지 재현하는 것을 공개 버전의 검증 기준으로 삼습니다.
